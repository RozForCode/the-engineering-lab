# 02 Computer Science Fundamentals

## A. Topic overview
This domain is a foundational pillar of modern engineering. It provides the theoretical and practical mechanisms used to reason about systems, solve problems, and build robust software.

A structured study path for core engineering fundamentals and applied practice.

The topic connects directly to software design, systems thinking, interviews, and production engineering.

## B. Learning objectives
- Understand the core concepts and terminology.
- Develop the ability to reason about internal mechanics and trade-offs.
- Apply the ideas to implementation exercises and engineering tasks.
- Connect this topic to adjacent domains such as systems, infrastructure, and architecture.

## C. Prerequisites
- Basic programming fluency.
- Comfort with reading technical explanations and writing disciplined notes.
- Familiarity with adjacent technical subjects.

## D. Detailed learning roadmap
### Stage 1: Foundations
- Concepts to study: vocabulary, core models, and common examples.
- Technical details: patterns, data flow, and where the concept matters.
- Questions to answer: what is it, why is it needed, and where is it used?
- Practical exercises: guided examples and small implementations.

### Stage 2: Implementation and reasoning
- Concepts to study: deeper mechanics, edge cases, and trade-offs.
- Technical details: asymptotic cost, failure modes, and system constraints.
- Questions to answer: how does the concept behave under stress or unusual inputs?
- Practical exercises: build implementations from scratch and validate them.

### Stage 3: Advanced mastery
- Concepts to study: optimization, invariants, design trade-offs, and advanced patterns.
- Technical details: execution models and reasoning under complexity.
- Questions to answer: when is this technique appropriate and when is it not?
- Practical exercises: compare multiple strategies and explain the trade-offs.

## E. Under-the-hood knowledge
- Understand the actual execution model rather than the simplified view.
- Study how the concept behaves in memory, time, or distributed systems.
- Focus on edge cases, invariants, and failure modes.

## F. Practical exercises
- Beginner: small examples and explanation exercises.
- Intermediate: implement real behavior with edge cases considered.
- Advanced: design or implement a system that incorporates multiple ideas.

## G. Interview preparation
- Practice common patterns and explain reasoning clearly.
- Focus on time complexity, trade-offs, and correctness arguments.
- Learn to speak through the design and implementation choices.

## H. Mastery checklist
- [ ] I can explain the concept in plain language.
- [ ] I can describe the internal mechanics accurately.
- [ ] I can implement it from scratch.
- [ ] I can explain edge cases and failure scenarios.
- [ ] I can explain when it is useful and when it is not.

## I. Mastery assessment
### Level 1: Foundational understanding
I can explain the core idea, terminology, and uses of the concept with examples.

### Level 2: Proficient implementation and application
I can implement the concept correctly and apply it to examples and design problems.

### Level 3: Deep technical mastery
I can explain the underlying system model, weigh trade-offs, and adapt the concept to unfamiliar scenarios.

## J. Learning resources
- Official documentation and language references.
- University lecture notes or engineering curriculum materials.
- Established engineering texts and practical writing from credible sources.
- Reputable coding and systems blogs.
